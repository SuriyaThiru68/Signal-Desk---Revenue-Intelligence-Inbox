Signal Desk · interface choices
02 / 05
What I built, and what I deliberately left out

Make the next decision inspectable, not the dashboard impressive.

In the first screen

  • Three fixed brief priorities with evidence references and a direct route into the source record.
  • Coverage, routing and review counts with a visible denominator and a “How it is counted” note.
  • Working source-type, person and route filters. Meeting organisers are separated from call reps.
  • An attention queue, activity by hour and person rows that open the underlying records.
  • Every record has a state. Intake and capture gaps are first-class, not hidden in a chart.
Overviewpriorities, KPIs, activity
Inboxsource-level search
Detailquotes, routes, audit
Brieffixed manager summary
Exportsreal files + manifest
Methoddefinitions and limits

Deliberately left out

  • Pipeline totals and forecasts. There is no authoritative deal value or opportunity table.
  • Cross-person performance rankings. The extract is selected for variety, not a representative sample.
  • Account merging. Similar titles and organiser domains do not prove the same conversation.
  • Generic summaries for silent records. No text means no substantive analysis.
  • A live AI integration. Pre-generated analysis is transparent and the app still handles new content.
Interaction principle: a route chip is a decision. Clicking one saves a manual override immediately, shows it separately from the suggestion, writes an audit entry and survives a source update until explicitly reset.
Interface review path: Overview → person or route → Inbox → Detail → Evidence / Source excerpt.Clickable corrections, not screenshots.

Signal Desk · trade-offs and next
05 / 05
Trade-offs, AI usage, limitations

I chose evidence integrity over a more commercial-looking dashboard.

Rejected: auto-merge and invent a deal

The tempting alternative was to merge M04/M13 into one Cedarwave account conversation, create an opportunity and attach a pipeline value. The data does not establish same conversation, sales ownership, opportunity or authoritative value. I kept the records separate and flagged the uncertainty.

AI disclosure

  • Pre-generated: 18 evidence-backed analyses with 89 exact passages, versioned by source revision.
  • Runtime: imports, de-duplication, revisions, filters, metrics, routes, review states, audit history, manifest and file generation.
  • No keys, no live model calls. A new revision without an analysis is shown as needing review, not as old analysis.

Known limitations

  • No CRM table, account history, confirmed staff roles or authoritative deal value.
  • 26 records have no usable text: 20 background calls, 3 silent meetings and 3 capture gaps.
  • Transcripts are adapted; a quote is evidence of the supplied text, not the underlying commercial fact.
  • The app is local-first; state lives in browser localStorage.

What I would improve next

  • Add a review-state filter and a “stale analysis” work queue.
  • Make the evidence card highlight the exact sentence in the transcript rather than the containing turn.
  • Add a real import diff view for a revised record.
  • Record the three-minute workflow with spoken narration using the provided script.

Run it

App: npm install && npm run dev · opens in the post-update demo state. Replay: Imports & replay → reset to empty → import initial → repeat shuffled → correct M07 → import update → refresh. Outputs: Download ZIP from any page, or npm run generate:exports for exports/ and exports-replay-demo.zip.
